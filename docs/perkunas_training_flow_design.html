Engineering Flow Map

Streaming Training Built for Bounded Memory

Perkunas trains large language model checkpoints through a streamed execution loop: compact active residency, replayable boundary traces, guarded updates, durable publishing, and telemetry that makes every phase measurable.

End-to-End Flow

Training Control Plane

The trainer coordinates data loading, segment activation, trace staging, replayed backward passes, candidate update publication, validation, and telemetry. Each phase has a narrow contract so the system can be tuned without changing the checkpoint format.

Step Lifecycle

One Training Step

A step is treated as a candidate state transition. It is measured, guarded, and published only after the active working store has a coherent set of segment updates.

1

Read Packed Tokens

Load fixed-length token windows and accumulate the configured micro-batches.

2

Build Forward Trace

Run streamed forward compute and keep only boundary tensors needed for replay.

3

Replay Backward

Reload one active segment at a time, recompute local forward, and propagate gradients.

4

Apply Safety Rails

Clip gradients globally or locally; guard can retry with scaled learning rate and norm budget.

5

Stage Candidate Update

Write parameter and optimizer updates into a transaction area before publishing.

6

Commit and Measure

Publish accepted state, prime prefetch, validate on schedule, and append telemetry.

Forward and Backward

Trace Staging Design

The forward pass does not retain a full autograd graph. Instead, it records boundary tensors that backward replay can restore later. The trace storage target is now configurable.

Same-GPU trace staging can reduce CPU round trips, but it uses the training GPU's VRAM. Secondary-GPU staging keeps the low-memory design while replacing CPU traffic with GPU-to-GPU traffic.

Safety Overlay

Guarded Step Replay

Guarded replay treats each update as a proposal. If the replayed batch does not stay within the configured tolerance, the trainer retries with scaled learning rate and gradient norm budget.

Observability

Telemetry Surfaces

The training log is designed to explain both learning behavior and system behavior. The same stream powers dashboard views for loss curves, spikes, replay attempts, device traffic, residency, validation, and throughput.

Learning Signals

train loss, validation loss, perplexity, rolling noise, guard loss delta

global gradient norm, clip scale, per-step accepted learning rate

System Signals

param load, module build, h2d, kernel time, trace stage and restore

active residency, cached segments, optimizer residency, memory peaks

Decision Signals

accepted replay attempts, retry count, effective LR scale, norm scale

validation regressions, spikes above threshold, degraded throughput

Operational Modes

Trace and Prefetch Choices

The training system separates two concerns: prefetch controls where upcoming parameter payloads are staged, while trace storage controls where forward boundaries and backward boundary gradients are staged.

Lowest VRAM

Keep traces on CPU. This is slower but safest when the active GPU is memory constrained.

--trace-storage cpu

Same-GPU Speed Test

Stage traces on the training GPU. Useful when VRAM headroom exists and CPU traffic is dominant.

--trace-storage gpu

Second-GPU Staging

Use another CUDA device as a fast trace shelf without changing the training compute GPU.

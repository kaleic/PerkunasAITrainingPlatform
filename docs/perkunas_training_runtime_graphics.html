Internal Engineering Visual

Training flow, replay, and durable update path.

A visual companion for the Perkunas v2 training loop: configuration enters the streaming trainer, data is packed into locality-preserving batches, each shard is activated on demand, boundaries are staged, replay performs local updates, and telemetry records the step.

Streaming execution Boundary activation trace Guarded replay Transactional writes

02 Data enters as packed arrays through a locality-preserving iterable loader.
03 Forward saves compact boundaries instead of holding the whole model graph.
04 Backward replay updates one shard slice at a time, then commits transactionally.

Sequence

One microbatch through forward trace and backward replay

The sequence shows when shards are loaded, where the boundary trace is saved, when a transaction begins, and how candidate guard attempts decide whether staged files are committed.

Forward trace

The trainer streams through embeddings, each block, and final normalization while storing only the boundary activations needed to replay local gradients later.

Backward replay

Reverse-order replay reloads each parameter and optimizer shard, recomputes the local forward, applies the update, and stages the result without exposing a partial checkpoint.

Guard Path

How guarded replay protects the step

Guarded replay acts like a local acceptance test. The same batch is checked after the staged update; if the loss exceeds tolerance, the transaction is aborted and retried with safer scales.

Acceptance gate

Loss must stay within tolerance before the staged update becomes durable.

Retry ladder

Candidate attempts can reduce learning rate scale and gradient norm scale.

Telemetry trail

Every attempt records scales, accepted loss, global norm, and clipping behavior.
